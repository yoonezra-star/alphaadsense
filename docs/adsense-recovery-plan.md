# Alpha AdSense 저가치 콘텐츠 거절 개선 계획

작성일: 2026-10-26
상태: 중복 정리·색인 확인 2개를 추가해 총 8개 글의 개별 본문과 공개 반영을 확인했다. 기존 도구·탐색 개선도 유지했다. 나머지 26개 글의 편집/병합과 재검토 신청은 아직 수행하지 않았다.

## 1. 목표와 판단 범위

목표는 승인용 외형을 늘리는 것이 아니라 초보 사이트 운영자가 문제를 해결하고 다시 사용할 이유가 있는 독립적인 운영 자료실을 만드는 것이다.

- 내부 품질 목표는 100점 중 90점 이상이다. Google의 공식 점수나 승인 확률이 아니다.
- 이전에 제시한 93점은 구조와 구성요소 존재 여부에 치우친 평가였다. 실제 콘텐츠 가치와 승인 가능성을 나타내는 수치로 사용하지 않는다.
- 거절 메시지는 개별 문제 URL이나 정확한 심사 근거를 알려 주지 않는다. 아래 발견 사항은 실제 소스와 공개 페이지에서 확인한 위험 요인이지 Google의 내부 판단을 확정한 것이 아니다.
- 글 수, 글자 수, 이미지 수, 고정 대기 기간, 일 방문자 수를 임의의 필수 승인 기준으로 만들지 않는다.
- Search Console의 검색 색인, AdSense 사이트 심사, Search Console 직접 조치는 각각 구분한다. 이번 안내만으로 검색 직접 조치가 있다고 판단하지 않는다.
- 검토 전용 화면, 사용자 에이전트별 다른 본문, 일시적인 품질 개선 후 원상 복구를 사용하지 않는다.

## 2. 실제 확인 결과

### 확인한 환경

- 소스 저장소: `D:/000 인컴님 다마고치/alphaadsense`
- 사용자 환경의 `D:/000 인컴님 다마고치/omybusiness/alphaadsense`는 확인 당시 비어 있었다. 소스를 이동하거나 복제하지 않았다.
- 실제 사이트: <https://alphaadsense.com/>
- 주요 생성 코드: `scripts/build.mjs`
- 로컬 상세 가이드 34개, 공개 사이트맵 URL 62개 확인.
- 실시간 HTTP 확인: 홈, Cloudflare/Search Console 예시 글, 사이트맵, robots.txt, 도구 3개가 200 응답. 존재하지 않는 시험 주소는 404 응답.
- 확인한 주요 HTML에 기존 Google 소유권 인증 메타 태그가 남아 있다. 이것만으로 현재 계정의 Search Console 소유권 상태가 확인된 것은 아니다.
- 확인한 robots.txt에는 일반 크롤링 허용 규칙이 있다. 실제 Google 광고 크롤러의 접근 성공 여부는 별도 로그/계정 확인이 필요하다.
- 로컬 및 공개 도구의 인라인 스크립트 구문 검사는 통과했다. 브라우저 상호작용과 실제 사용성 검사를 통과했다는 뜻은 아니다.
- 현재 Search Console 수치, AdSense 계정 화면, 방문자 통계, 모바일 실기기 사용성은 이번 진단에서 확인하지 않았다.

## 3. 단계별 실행

### 1단계: 전체 글의 역할 결정 및 반복 본문 개선

실행:

1. 34개 글 각각에 독자 질문, 현재 답, 부족한 근거, 유지/재작성/병합 판단을 기록한다.
2. 공통 도입, 공통 실행 순서, 내용과 맞지 않는 자동 표, 카테고리별 반복 본문을 제거할 대상으로 표시한다.
3. 글의 본문과 메타데이터를 개별 관리할 수 있도록 생성 구조를 최소한으로 변경한다.
4. 첫 대표 글인 `low-value-content-fix`를 실제 alphaadsense의 반복 문장과 수정 전후 비교를 바탕으로 재작성한다.
5. 반복 부분만 삭제해서 더 빈약해진 페이지를 배포하지 않는다. 본문 대체 또는 병합 처리가 준비된 단위로 배포한다.

완료 조건:

- 34개 글에 처리 방침이 모두 기록되어 있다.
- 첫 대표 글이 원인 분류, 실제 예시, 수정 선택 기준, 검증 절차까지 제공한다.
- 공통 레이아웃이나 짧은 고지를 제외한 긴 일반론이 여러 글에 자동 삽입되지 않는 구조가 마련된다.
- 배포하는 글에 준비 중 문구, 비어 있는 섹션, 제목과 무관한 표가 없다.

병합/역할 조정 후보. 최종 결정 전 검색 유입과 기존 링크도 확인한다:

| 글 묶음 | 검토 방향 |
| --- | --- |
| `low-value-content-fix` / `low-value-rejection-rewrite-example` | 해결법을 대표 문서로. 예시 글은 실제 고유한 전후 분석이 있을 때만 분리 |
| `site-structure-before-apply` / `site-structure-audit-example` / `homepage-for-review` | 구조 설명과 실제 감사 기록의 역할 분리. 내용이 겹치면 대표 문서로 병합 |
| `privacy-policy-for-adsense` / `cookie-notice-basics` / `privacy-cookie-page-example` | 안내서, 쿠키 개념, 실제 예시를 구분. 일반 문장만 다른 글은 합침 |
| `content-calendar-30-days` / `evergreen-content-plan` / 계획 도구 | 장기 운영 전략과 사용자가 직접 편집하는 계획표만 분리 |
| `pre-apply-checklist` / `/checklist/` / 점수 도구 | 하나의 실용 점검표로 역할 통합 검토 |
| `glossary-for-beginners` / `rpm-cpc-basics` | 용어집은 짧은 참조용, RPM 글은 계산 및 해석용 |
| `/official-resources/` / `/sources/` | 독자용 공식 링크 모음과 편집 출처 원칙을 구분하거나 통합 |
| 시작 가이드 / 승인 허브 / 로드맵 / 다음 단계 | 같은 링크를 나열하는 중간 페이지를 줄이고 대표 경로로 연결 |

병합 시에는 내용이 실제로 대체되는 주소로 영구 리디렉션하고 내부 링크, canonical, 사이트맵을 함께 갱신한다. 무관한 모든 URL을 홈으로 보내지 않는다. `noindex`나 robots 차단만으로 저가치 콘텐츠 문제가 해결되었다고 간주하지 않는다.

### 2단계: 대표 콘텐츠 6개 제작 및 나머지 글 전수 편집

6개는 프로젝트의 우선 작업 묶음이며 Google의 최소 글 수가 아니다. 대표 글만 개선하고 나머지 빈약한 글을 그대로 두지 않는다.

| 우선 제작 문서 | 제공할 고유한 가치 | 증거와 검증 |
| --- | --- | --- |
| 낮은 가치 거절 후 콘텐츠 정리 | 이 사이트의 반복 문장, 유지/병합 판단, 전후 비교 | 소스 및 공개 페이지에서 확인한 실제 예시. 승인 성공 사례로 표현하지 않음 |
| 가비아 도메인과 Cloudflare Pages 연결 | 등록기관과 DNS 호스팅의 차이, 메일 DNS 보존, 연결/복구 절차 | 최신 공식 화면과 문서. 계정 화면은 접근 가능할 때만 개인정보를 가리고 사용 |
| Search Console 소유권 인증 문제 해결 | 도메인 속성 DNS TXT와 URL 접두어 HTML 태그 차이, 실패별 분기 | 실제 배포 HTML, DNS 확인 절차, 재검증 결과 |
| 정보 글을 문제 해결 글로 편집하는 방법 | 하나의 구체적인 글을 처음부터 끝까지 바꾸는 편집 사례 | 수정 전후 문장, 바꾼 이유, 출처 검증. 가상 예시는 가상이라고 명시 |
| RPM/CPC/CTR 계산 및 해석 | 페이지 조회와 광고 노출 구분, 직접 계산, 비교 시 주의점 | 공식 수식과 테스트값. 가상 수익과 실제 수익을 명확히 구분 |
| 실제 사이트 구조 감사 | 홈에서 답에 도달하는 경로, 중복 허브, 모바일 표/메뉴 개선 | 데스크톱/모바일 전후 화면과 작업 결과 |

각 문서는 제목의 질문에 직접 답하고, 조건별 절차, 예상 결과, 실패 시 대안, 관련 주장에 맞는 출처를 갖춘다. 불필요한 고정 목차를 모든 글에 강요하지 않는다.

완료 조건:

- 출처가 필요한 정의와 정책 주장을 원문과 대조했다.
- 직접 확인한 사실, 운영자의 제안, 설명을 위한 가상 예시가 구분된다.
- 허구의 승인 사례, 수익 인증, 전문가 경력, 고객 후기가 없다.
- 남은 모든 글도 개별 역할과 실질적인 답을 갖추거나 적절히 병합되었다.

### 3단계: 도구를 실제 작업 공간으로 개선

우선 도구는 콘텐츠 점검 작업표와 RPM 계산기다. 단순 선택지별 안내는 자동 사이트 진단이라고 표현하지 않는다.

- 콘텐츠 작업표: 글 URL, 해결 질문, 직접 확인한 자료, 중복 대상, 수정 작업, 상태, 검토일 입력.
- 입력값을 바탕으로 미완료 항목과 다음 행동을 보여 주고 로컬 저장, 초기화, CSV 내보내기를 제공.
- 로컬 저장 범위와 삭제 방법을 알리고 실제 전송 여부를 개인정보 안내와 일치시킴.
- RPM 계산기: 수입, 페이지 조회 또는 광고 노출, 통화 단위, 계산 근거를 명시. 세션 수와 혼동하지 않음.
- 0 나누기, 빈 입력, 음수, 소수, 비정상 값, 긴 URL, 키보드 조작, 저장 실패, 초기화 상태를 검사.
- 기존 승인 점수는 승인 확률이나 재신청 허가처럼 해석되지 않도록 교체. 사이트를 읽지 않는 도구는 검사했다고 말하지 않음.

완료 조건: 도구의 입력, 출력, 저장/삭제/내보내기가 브라우저에서 작동하고 사용자가 실제 결과물을 가져갈 수 있다.

### 4단계: 독자 중심 탐색과 시각 자료

- 홈의 페이지 수 홍보와 사이트 구성 설명을 줄이고 주요 질문과 실제 자료를 보여 준다.
- 처음 만드는 사람과 거절을 해결하는 사람의 시작 경로를 분명히 한다.
- 독자에게 별도 도움이 없는 중간 허브를 계속 늘리지 않는다.
- 글 상세에는 필요한 경우 목차, 단계별 화면, 해당 주제에 맞는 관련 문서를 제공한다.
- 이미지는 실제 화면, 직접 작성한 설명 자료, 전후 비교처럼 정보 전달에 쓰인다. 장식용 스톡 사진을 채우지 않는다.
- 표는 분류와 값이 실제로 비교 가능한 경우에만 사용한다. 글머리표를 똑같이 표로 재출력하지 않는다.
- 모바일에서 메뉴 조작, 긴 표, 이미지, 긴 제목, 본문 확대, 키보드 초점을 확인한다.
- 향후 자동화 서비스는 출시 전까지 이용 가능한 기능인 것처럼 보여 주지 않는다.

완료 조건: 새 방문자가 첫 화면에서 필요한 문서를 찾고, 글을 읽고, 관련 작업 도구로 이동해 결과를 남길 수 있다. 핵심 경로의 데스크톱/모바일 화면 검사를 통과한다.

### 5단계: 신뢰, 운영 정보, 기술 검증

- 리플리더스 사업자 정보와 문의 경로는 유지하되 모든 본문에 긴 사업자 표를 반복하지 않는다.
- 작성/검토 책임과 실제 작업 방식을 소개한다. 없는 편집 인력이나 경력을 추가하지 않는다.
- 글별 실질적 수정일과 변경 내용을 관리하고 최근 글은 실제 날짜로 정렬한다.
- 개인정보 및 쿠키 고지는 실제 광고/분석/호스팅/문의 처리와 대조한다. 현재 사용과 향후 계획을 분리한다.
- 애드센스용 문서라는 이유로 약관, 면책, 쿠키 문서를 모두 독립 페이지로 만들면 승인이 보장된다고 안내하지 않는다.
- 사이트맵, 내부 링크, canonical, 리디렉션, 404, HTTPS, 인증 태그, 검색 기능을 검사한다.
- Googlebot/광고 크롤러의 실제 접근 가능성을 Cloudflare 설정 및 이용 가능한 로그에서 확인한다. 필요 이상의 보안 전체 해제를 하지 않는다.
- Search Console의 현재 소유권, 색인 현황, 직접 조치, 보안 문제를 계정에서 별도로 확인한다. 검색 색인이 심사 승인을 보장하지 않는다.

완료 조건: 핵심 정보의 사실 관계와 실제 운영이 일치하고, 공개 페이지가 사용자와 검토 크롤러에게 정상 제공된다.

### 6단계: 실제 사용 검증과 재검토

- 잠재 독자에게 관련 자료를 정상적으로 소개하고, 해결되지 않는 질문과 도구 오류를 수집해 수정한다.
- 조회수 구매, 클릭 교환, 지인 광고 클릭, 인위적인 체류시간 조작을 하지 않는다.
- 이용 가능한 Search Console/분석 자료로 검색 질문, 방문 경로, 도구 사용, 재방문을 확인한다. 수집 도구를 추가하면 고지와 필요한 동의를 먼저 검토한다.
- 운영 지속성은 실제 수정과 응답 기록으로 보여 준다. 날짜만 변경하거나 계획을 실행 실적으로 기록하지 않는다.
- 필수 대기 일수를 지어내지 않는다. 계정에 재요청 제한이 있으면 따르고, 수정한 공개 사이트가 안정적으로 제공되는지 확인한 뒤 판단한다.
- 아래 내부 평가와 차단 조건을 검토하고 실제 수정이 끝난 뒤에만 '문제를 수정했음을 확인합니다'를 선택한다.

## 4. 내부 품질 평가: 목표 90점 이상

각 항목은 확인한 산출물과 검사 결과가 있을 때만 부여한다. 현재는 항목별 검증이 끝나지 않았으므로 합계 점수를 산정하지 않는다. 미확인을 통과로 처리하지 않는다.

| 평가 항목 | 배점 | 확인할 산출물 |
| --- | --- | --- |
| 고유한 콘텐츠 | 45 | 전체 글의 질문 구분 10, 주제별 완결된 답 15, 직접 만든 분석/사례 10, 사실과 출처 검증 10 |
| 실용 도구와 자료 | 20 | 유효한 입력/출력 8, 저장/내보내기 등 작업 완료 6, 오류/경계값/접근성 검사 6 |
| 신뢰와 운영의 일치 | 15 | 운영자와 문의 사실성 5, 실제 처리에 맞는 개인정보 고지 5, 개별 수정 및 검토 기록 5 |
| 탐색과 모바일 사용성 | 10 | 주요 문제 해결 경로 4, 모바일 가독성과 표 3, 키보드/초점/명확한 이름 3 |
| 기술적 정상 제공 | 10 | 상태 코드/링크/리디렉션 4, canonical/사이트맵/인증 보존 3, 실제 접근과 배포 확인 3 |

정량 항목은 통과 사례 수/대상 수를 기록하고, 편집 판단 항목은 근거를 남긴다. 총점만 높이기 위한 구성요소 추가는 인정하지 않는다.

90점 이상이어도 다음 중 하나가 남아 있으면 재검토 요청을 보류한다:

- 공개된 주요 문서가 여전히 반복 일반론에 그치거나 제목의 답을 제공하지 않음.
- 잘못된 핵심 정의, 허구의 사례, 승인 보장 또는 제공하지 않는 기능을 약속함.
- 주요 도구가 작동하지 않거나 저장/전송 방식의 고지가 실제와 다름.
- 검토 경로의 접근 차단, 깨진 링크, 주요 문서의 오류가 해결되지 않음.
- 광고/개인정보 등 필수 정책 준수 항목을 아직 확인하지 못함.

## 5. 운영 원칙과 제외할 작업

- 이미 승인된 carspecial.kr의 탐색과 가독성은 참고할 수 있지만, 템플릿이 승인 원인이라고 단정하거나 문장을 복제하지 않는다.
- 다마고치와 같은 서비스의 외형보다 실제 가능한 기능과 정확한 설명을 우선한다.
- AI 사용 자체를 숨기기 위한 말투 수정이 목표가 아니다. 최종 작성자의 검증, 독창성, 책임이 중요하다.
- 페이지를 단순히 비공개로 숨기거나 검색에서만 제외해 AdSense 검토를 우회하려 하지 않는다.
- 도메인을 새로 사거나 사이트를 초기화하는 방법을 우선 처방하지 않는다.
- 이번 계획에서 실제로 수행하지 않은 수정, 사용자 반응, 승인 결과를 완료로 표시하지 않는다.

## 6. 공식 근거

확인일: 2026-10-26. 다음 문서는 개선 방향의 근거이며 이 계획의 배점이나 문서 수를 정한 자료는 아니다.

- [Google 애드센스 콘텐츠 및 사용자 환경](https://support.google.com/adsense/answer/10015918?hl=ko): 고유 가치, 사이트 내 중복 최소화, 유사 문서의 확장 또는 통합, 탐색 품질.
- [사이트 페이지가 애드센스 사용에 적합한 상태인지 확인](https://support.google.com/adsense/answer/7299563?hl=ko): 독창성, 사이트별 장점, 사용하기 쉬운 메뉴.
- [Google 게시자 정책](https://support.google.com/adsense/answer/10502938?hl=ko): 콘텐츠, 행위, 개인정보 등 준수 범위. 사용자 제공 9335564 링크는 확인 시 이 문서로 연결됨.
- [Google 웹 검색의 스팸 정책](https://support.google.com/publisherpolicies/answer/11035931): 가치 없는 반복 접근과 제공하지 않는 기능의 주장 경계.
- [사용자 중심 콘텐츠 제작](https://developers.google.com/search/docs/fundamentals/creating-helpful-content?hl=ko): 독창적 분석, 완결성, 정확성, 누가/어떻게/왜 작성했는지. 검색 품질 안내이며 별도의 AdSense 합격 점수표는 아님.
- [페이지 RPM](https://support.google.com/adsense/answer/112030?hl=ko): 예상 수입 / 페이지 조회수 * 1000.
- [1,000회 노출당 수익](https://support.google.com/adsense/answer/190515?hl=ko): 페이지 RPM과 광고 RPM의 분모 구분.
- [직접 조치 보고서](https://support.google.com/webmasters/answer/9044175): 검색 직접 조치와 AdSense 사이트 거절을 구분할 때 참고.
